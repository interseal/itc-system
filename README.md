# ИТК · хранилище кода (itc-system)

Главная копия кода компании ОсОО «ИТК». Закрытое хранилище: видит только владелец.
Рабочая копия — на сервере в Сингапуре (kosmos.itcpartner.store), он сам сверяется с GitHub.

**Ключей и паролей здесь нет и быть не должно.** Все ключи — только в сейфе Bitwarden (организация ITC).
Каталоги фабрик здесь не храним: они лежат в S3-хранилище магазина (таблица `itc_sup_media`, настройки `$S3_*` в config.php).
Копии баз — на ноутбуке и на сервере в Гуанчжоу (см. паспорт, раздел 8).

## Что где

| Папка | Что это |
|---|---|
| `store/` | магазин itcpartner.store и Экосистема (PHP + страницы). Выгрузка «Файлы для Claude» на №531 + изменения №532–№536 (№536 — общая память Фила и Космоса, готово, ждёт установки) |
| `site/` | сайт itcpartner.ru |
| `metro/` | «Мой Гуанчжоу» (metro.itcpartner.store) |
| `kosmos/` | «Космос»: сервер в Сингапуре (`lib`, `www`, `bin`, `install`), части магазина (`store`), сборка (`tools`), проверки (`tests`) |
| `docs/` | паспорт системы (`ITC_pasport_sistemy.md`), планы |
| `android/` | Android-приложения ИТК (проект `D:\Format\ITCApp`) — будет добавлен с ноутбука |

## Как вносятся изменения

1. Изменение делается здесь (коммит), проверки — `kosmos/tests`.
2. Из изменённых файлов собирается обновление `obnovlenie_N.zip` с подписью (`kosmos/tools/build_store_update.py`).
3. Руководитель ставит его: Экосистема → Обновления. Номер N = установленный + 1 (спросить у руководителя).

## Важно

- `store/api/webpush.php`: закрытый ключ уведомлений в этой копии вырезан. На сервере он пока в самом файле — перенести в config.php и Bitwarden (`VAPID_PRIVATE_PEM`), до этого файл отсюда в магазин не ставить.
- В коде есть несекретные служебные ключи: IndexNow (публичный по устройству), ключ сброса копии страниц `SUP_WEB_REFRESH_KEY`, ключ карт Яндекса в страницах (ограничен адресом сайта).
- Выгрузка магазина неполная: config.php и часть служебных файлов (например, `api/suppliers.php`) в неё не входят. Недостающие файлы добавим отдельно, без секретов.
- Сервер в Сингапуре только читает это хранилище (ключ доступа «только чтение», Deploy key) и раз в 10 минут обновляет свою копию в `/srv/itc-system`. Записывать сюда он не может.
