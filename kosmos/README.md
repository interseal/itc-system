# ИТК · «Космос» — исходники

Второй ИИ-помощник ИТК на Claude. Версия записана в `lib/boot.php` (KOSMOS_VERSION).
Подробности для руководителя — `ITC_Kosmos_plan.md`, для помощника — «Паспорт системы», разделы 4.8, 5.3, 12.
Ключей и паролей в исходниках нет.

## Что где

| Папка | Что внутри |
|---|---|
| `lib/` | ядро на PHP 8.3, подробности ниже |
| `www/` | `index.html` — экран «Космоса» (чат, память, настройки руководителя); `api.php` — все запросы экрана |
| `bin/` | `worker.php` — фоновые задачи (служба kosmos-worker); `agent.php` — обслуживание сервера |
| `install/` | `install.sh` (установка и обновление на Ubuntu 24.04), nginx, пул PHP-FPM, службы systemd |
| `store/` | файлы магазина: `api/kosmos.php` — связь с сервером; `api/kosmos_lib.php` — шлюз к Claude; `apps/kosmos/` — экран «Космоса» (копия «Фила», собирается скриптом) |
| `tools/` | `build_pkg.py` — пакет сервера с подписью; `build_store_update.py` — готовое обновление магазина; `make_kosmos_flow.py` и `make_kosmos_app.py` — «Космос» из «Фила» (api/flow.php → api/kosmos_flow.php, apps/fil → apps/kosmos) |
| `tests/` | пробный Claude и проверки |

Файлы ядра в `lib/`:
- `boot.php` — настройки и список моделей;
- `db.php` — база SQLite, один файл;
- `auth.php` — вход пропуском Экосистемы, доступ сотрудников, лимиты;
- `keys.php` — ключи Claude, зашифрованы AES-256-GCM;
- `claude.php` — запросы к Claude, ответ по мере написания;
- `memory.php` — память;
- `prompt.php` — правила и сборка запроса;
- `tools.php` — инструменты Claude;
- `chat.php` — разговор;
- `tasks.php` — фоновые задачи и сводки.

## С 0.2.0 / №533: «Космос» = «Фил» на Claude

- Пользователи работают в `itcpartner.store/apps/kosmos/` — это экран «Фила» один в один. Данные CRM обрабатывает магазин (`api/kosmos_flow.php` — копия `flow.php`, своя переписка `itc_ks_*` и настройки `ks_*`).
- Думать магазин просит этот сервер: `POST /api.php?a=gw` с заголовком `X-Kosmos-GW` (ключ шлюза: магазин создаёт, агент получает в ответ на отчёт и кладёт в `/etc/kosmos/gw.key`). Код шлюза — `lib/gw.php`: доступ сотрудников, лимиты, ключи Claude, запасной ключ, кеш правил.
- Агент раз в минуту будит фоновые задачи «Космоса» в магазине (адрес `cron` из ответа на отчёт).
- Экран этого сервера (`www/index.html`) теперь нужен руководителю для настроек: «Космос» в магазине открывает его поверх страницы (`#t=…&set=keys`).
- После изменений «Фила»: `python3 tools/make_kosmos_flow.py flow.php kosmos_flow.php` и `python3 tools/make_kosmos_app.py apps/fil apps/kosmos <картинки>`.

## 0.2.1 / №534, №535 (13.11.2026)

- Личные ключи Claude без рабочей области: сервер сам находит рабочую область (`GET /v1/organizations/workspaces?include_default=true`), выбирает единственную или «Default», запоминает у ключа (`keys.ws`, `keys.ws_name`) и шлёт `anthropic-workspace-id` в каждом запросе. Выбрать нельзя — у ключа кнопка «Рабочая область».
- Поле ключа — текстовое со скрытием символов, чтобы браузер не подставлял сохранённые пароли.
- Магазин (№535): ответ Claude разбирает `ks_ai_json` в `store/api/kosmos_lib.php` (первый целый JSON, текст вокруг, переводы строк внутри строк, ответ без JSON); при `max_tokens` — повтор с 16000.
- Модели 5.5 думают сами, если `thinking` не задан (мысли тратят `max_tokens`). Чат на самом сервере пока не собирает `thinking_delta`/`signature_delta` из потока — исправить в 0.2.2, если им будут пользоваться с инструментами.

## Главное устройство

- Ничего не хранится в аккаунте Anthropic. Каждый запрос собирается из нашей базы: правила, память, сводка, последние сообщения. Поэтому ключ любого аккаунта даёт ту же картину.
- Быстрая модель отвечает сразу. Долгую работу она передаёт инструментом `start_task`. Служба worker выполняет её сильной моделью и кладёт итог в тот же разговор.
- Вход: экран отправляет пропуск Экосистемы в заголовке `X-Eco-Token`. Сервер проверяет его у магазина: `api/kosmos.php?a=who`, служебный ключ в заголовке `X-Kosmos-Token`.

## Проверки

Запускаются из этой папки, нужны PHP 8.3 (sqlite3, curl, mbstring, sodium) и Python 3.

- `python3 tests/run_tests.py` — ядро: ключи, память, смена ключа, задачи, доступ, лимиты (48 проверок).
- `python3 tests/ui_test.py` — экран в Chrome: компьютер и телефон (17).
- `python3 tests/store_e2e.py` — магазин, настоящая установка сервера, nginx, PHP-FPM, агент, версии с подписью. Запускать от root, в одноразовой среде (46).
- `python3 tests/store_ui_test.py` — страница магазина: подключение по шагам, «Космос» и «Фил» рядом (12).

## Выпуск новой версии

1. Поднять `KOSMOS_VERSION` в `lib/boot.php`, прогнать проверки.
2. Спросить у руководителя номер последнего установленного обновления. Новое = он + 1.
3. Собрать обновление:
   `python3 tools/build_store_update.py --n <номер> --upd-key upd_key.php --sign-key kosmos_sign.pem --out obnovlenie_<номер>.zip`
   - UPD_KEY и KOSMOS_SIGN_KEY — из Bitwarden, проект `dev`;
   - ключи после сборки удалить с диска.
4. Прислать архив руководителю в чат. Он ставит его в Экосистеме → Обновления.
5. Сервер «Космоса» сам заберёт новую версию за 10 минут.
