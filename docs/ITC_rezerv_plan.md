# Резервный сервер «Космоса» — задача (поставлена руководителем 14.11.2026, срок: 21–28.11.2026)

## Зачем
Все наши серверы — у одного поставщика, Aliyun (Гуанчжоу, Гонконг, Сингапур). Если Aliyun откажет целиком (сбой, блокировка аккаунта, санкции, оплата), лягут все три. Нужен второй сервер у **другого поставщика в другой стране** (например, Малайзия), без санкционных рисков, — чтобы работа и данные продолжались.

## Что уже лежит вне Aliyun (на 14.11.2026)
- Код — GitHub (interseal/itc-system).
- Ключи и пароли — Bitwarden (проекты dev, store, «Авто»).
- Ночные резервные копии базы «Космоса» — в магазине на reg.ru (другой поставщик, но тоже одна точка).
- Магазин и Экосистема — reg.ru (не Aliyun).
Чего нет: второго **работающего** сервера «Космоса» — сейчас при падении Сингапура пришлось бы ставить новый вручную.

## План
1. Выбрать поставщика и страну (Claude ищет, руководитель решает): не Aliyun и не китайский; принимает оплату, доступную ИТК; нет санкционных ограничений для Кыргызстана; 2–4 vCPU, 4–8 ГБ. Проверить варианты в Малайзии, Сингапуре и Европе.
2. Купить (покупает и оплачивает руководитель), пароль root — в Bitwarden «Авто».
3. Поставить «Космос» тем же установщиком (kosmos/install/install.sh) в режиме **резерва**: каждый час забирает свежую копию базы и рабочую копию GitHub, ключи — из Bitwarden; сам не отвечает, пока основной жив.
4. Переключение: если основной не отвечает N минут — руководитель одной кнопкой (или автоматически) переводит kosmos.itcpartner.store на резерв. Учесть, что DNS тоже у reg.ru.
5. Разработчик (Космос/Фил) — тоже на резерве: Claude Code ставится так же.
6. Проверка «учебной тревогой»: выключить основной, убедиться, что Фил и «Космос» работают через резерв, данные на месте.
7. Потом: подумать о зеркале магазина (reg.ru — тоже одна точка).
