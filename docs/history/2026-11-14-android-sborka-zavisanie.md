# 14.11.2026 — почему с 14:00 не приходили обновления (разбор в глубину)

Симптом: сборка Android-приложений на сервере «Космоса» «качала Android Studio» с 14:00 до вечера, обновления не приходили, Claude несколько раз переставлял очередь — не помогало.

Причины (все в коде агента и скрипта сборки):
1. **Замок агента наследовался фоновой сборкой.** `nohup php agent.php android N &` из прохода агента получал открытый `kosmos-agent.lock`. Пока шла сборка (до часа и дольше, плюс её дочерние процессы), КАЖДЫЙ проход агента выходил «уже работает другой проход»: не было ни git pull, ни сборки обновлений, ни отчёта в магазин, ни самообновления. Поэтому перестановка очереди ничего не меняла — сервер её просто не видел. Проверено локально: старый способ держит замок, новый — нет.
2. **Установка Java через apt.** Первая сборка ставила openjdk через apt; ограничение `timeout 3600` обрывало apt посреди установки → «dpkg was interrupted» → следующая сборка чинила dpkg и ждала блокировок по 15 минут ×3 → снова обрыв. Круг.
3. **Не было видно, что происходит.** Ни ход сборки, ни то, что агент вообще перестал отзываться, нигде не показывались.
4. Цепочка «после №…» в одном проходе (агент писал state.json только в конце) — обновления ссылались не на установленное.

Исправлено (агент 0.4.8, №591):
- `a_bg()` — фоновые задачи (Android, devrun) закрывают унаследованные дескрипторы; агент больше не блокируется.
- `build_android.py`: Java 17 — архивом Eclipse Temurin в /opt/jdk-17 (без apt/dpkg), загрузки с видимым ходом и пределом 30 минут на файл, пределы времени для sdkmanager, файл хода `status.json`.
- Агент отдаёт в магазин ход сборки (`android`: номер, шаг, сколько идёт, ошибка); магазин хранит версию агента и время последнего отчёта.
- Страница «Обновления»: «Сервер «Космоса» 0.4.8 на связи (2 мин назад)», «Собирает Android: шаг, сколько идёт», а если сервер не отзывается больше 20 минут — красная плашка с подсказкой перезапустить.
- state.json сохраняется после каждого обновления; Android и ошибки не останавливают остальные (continue).

Что сделать руководителю: один раз перезапустить сервер в консоли Aliyun (снять зависшую сборку), поставить №591. После этого Android-приложения (android_pending/592b–594b) вернуть в очередь.
